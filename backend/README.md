# Todo API Backend

FastAPI backend for Todo application with JWT authentication and Neon PostgreSQL persistence.

## Features

- RESTful API for task CRUD operations
- JWT-based stateless authentication
- User data isolation (users can only access their own tasks)
- Filtering by completion status (all, pending, completed)
- Sorting by creation date (newest first) or title (alphabetical)
- Toggle task completion status

## Getting Started

### Prerequisites

1. **Install Python 3.11+** (if not already installed)
2. **Clone this repository** and navigate to the `backend/` directory
3. **Create virtual environment**:
   ```bash
   cd backend
   python -m venv venv
   # Windows:
   venv\Scripts\activate
   ```

4. **Install dependencies**:
   ```bash
   # Activate virtual environment
   # Windows:
   venv\Scripts\pip install -r requirements.txt
   ```

5. **Configure environment variables**:
   ```bash
   # Copy the example and update with your values
   cp .env.example .env
   # Edit .env to add:
   # BETTER_AUTH_SECRET=your_shared_secret_here
   # DATABASE_URL=postgresql://user:password@host:port/database?sslmode=require
   ```

### Environment Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `BETTER_AUTH_SECRET` | Shared secret for JWT signing/verification. Must match frontend's value. | `9LwoNRSxkGnLUquJlXdVmRCg3cIjSnhi` |
| `DATABASE_URL` | PostgreSQL connection string for Neon database. | See `.env.example` |

**IMPORTANT**: Never commit `.env` file to version control. Use `.env.example` as a template.

## Running the Server

### Development

```bash
# Activate virtual environment
# Windows:
venv\Scripts\activate

# Run the server
uvicorn main:app --reload --port 8000
```

The API will be available at:
- **API**: `http://localhost:8000/api`
- **Swagger UI**: `http://localhost:8000/docs`
- **OpenAPI JSON**: `http://localhost:8000/openapi.json`

## API Endpoints

### Task Management

All endpoints require JWT authentication via `Authorization: Bearer <token>` header.

| Method | Endpoint | Description | Auth |
|--------|----------|-------------|------|
| GET | `/api/tasks` | List tasks with optional filtering and sorting |
| POST | `/api/tasks` | Create a new task |
| GET | `/api/tasks/{id}` | Get a specific task |
| PUT | `/api/tasks/{id}` | Update a task (partial updates) |
| DELETE | `/api/tasks/{id}` | Delete a task |
| PATCH | `/api/tasks/{id}/complete` | Toggle task completion |

### Query Parameters

#### List Tasks (`GET /api/tasks`)

| Parameter | Type | Values | Default | Description |
|-----------|------|--------|-------------|
| `status` | string | `all`, `pending`, `completed` | `all` | Filter by completion status |
| `sort` | string | `created`, `title` | `created` | Sort order |

### Request/Response Examples

#### Create Task

**Request:**
```http
POST /api/tasks
Authorization: Bearer <your_jwt_token>
Content-Type: application/json

{
  "title": "My first task",
  "description": "Optional description"
}
```

**Response (201 Created):**
```json
{
  "id": 1,
  "user_id": "user_123",
  "title": "My first task",
  "description": "Optional description",
  "completed": false,
  "created_at": "2026-01-03T10:00:00Z",
  "updated_at": "2026-01-03T10:00:00Z"
}
```

#### List Tasks

**Request:**
```http
GET /api/tasks?status=pending&sort=title
Authorization: Bearer <your_jwt_token>
```

**Response (200 OK):**
```json
{
  "tasks": [
    {
      "id": 1,
      "user_id": "user_123",
      "title": "Buy groceries",
      "description": null,
      "completed": false,
      "created_at": "2026-01-03T10:00:00Z",
      "updated_at": "2026-01-03T10:00:00Z"
    }
  ]
}
```

### Authentication

The backend verifies JWT tokens on every request. The token must be:
- Generated by Better Auth on the frontend
- Signed with the same `BETTER_AUTH_SECRET` as the backend
- Passed in the `Authorization: Bearer <token>` header

### Error Responses

| Status | Description | Response Format |
|--------|-------------|----------------|
| 401 Unauthorized | Missing, invalid, or expired JWT | `{"detail": "Authentication required"}` |
| 403 Forbidden | User doesn't own the resource | `{"detail": "Access denied"}` |
| 404 Not Found | Resource doesn't exist | `{"detail": "Task not found"}` |
| 422 Unprocessable Entity | Validation error | `{"detail": "Invalid input data"}` |

## Security Notes

- All database queries filter by authenticated `user_id` - cross-user access is impossible
- JWT tokens are verified on every request - no session storage (stateless)
- CORS is configured for `http://localhost:3000` in development
- Database connection string and `BETTER_AUTH_SECRET` must match between frontend and backend

## Database Schema

### Users Table (managed by Better Auth)
- `id`: varchar, primary key
- `email`: varchar, unique, not null
- `name`: varchar, nullable
- `created_at`: timestamp

### Tasks Table (managed by backend)
- `id`: integer, auto-increment primary key
- `user_id`: varchar, foreign key to users.id
- `title`: varchar(200), not null
- `description`: text, nullable, max 1000 chars
- `completed`: boolean, default false
- `created_at`: timestamp, auto-generated
- `updated_at`: timestamp, auto-updated on modification

**Indexes**: `ix_task_user_id` (for efficient per-user queries), `ix_task_completed` (for status filtering)

## Frontend Integration

The frontend should:
1. Use Better Auth for user authentication and JWT token generation
2. Store the JWT token in localStorage/session storage
3. Include the JWT in the `Authorization: Bearer <token>` header for all API requests
4. Handle 401 responses by redirecting to login
5. Use the API client functions from `frontend/src/lib/api.ts`

## Troubleshooting

### Backend won't start
- Verify Python 3.11+ is installed
- Verify virtual environment is activated
- Check that all dependencies are installed: `pip list`
- Verify environment variables are set in `.env`

### Database connection errors
- Verify `DATABASE_URL` is correctly formatted
- Check network connectivity to Neon PostgreSQL
- Ensure SSL settings: `sslmode=require`

### JWT authentication errors
- Verify `BETTER_AUTH_SECRET` matches between frontend and backend
- Check that token is being sent in the correct format: `Authorization: Bearer <token>`
- Verify token hasn't expired
- Check FastAPI logs for specific error messages
